# ADR 0005：自定义控制器经 RS232-USB 接入，客户端侧保留 UDP 兼容路径

- 状态：accepted
- 日期：2026-10-19
- 决策人：RM26 客户端维护团队

## 背景

官方通信协议里，自定义控制器（命令码 `0x0302`，上限 30 Hz）与自定义客户端
（命令码 `0x0310`，上限 50 Hz）原本是两个独立角色：自定义控制器走 RS232，自定义
客户端走 RJ45。合并为同一套客户端后，链路需要重新划定。

控制器的实际发送端是 STM32 UART7（`stm32h7xx`，115200 8N1），`Video_Link_Task`
每 `TX_PERIOD`（34 ms，约 29 Hz）发送一帧：

```text
SOF(0xA5) | data_length(2, 小端) | seq(1) | CRC8(1)
| cmd_id(2, 小端, 0x0302) | data(30) | CRC16(2, 小端)
```

客户端主机没有原生 RS232 接口，只有 USB / 以太网 / Wi‑Fi。因此必须先把 RS232 转成
主机可用的端口。

## 决策

采用 **RS232-USB 转换器 + 虚拟串口** 作为现场主链路：

```text
控制器 UART7(TX) --RS232-- RS232-USB 转换器 --USB-- 主机虚拟串口(/dev/ttyUSBx)
```

客户端 `CustomControllerReceiver` 默认按串口打开该虚拟串口（默认 115200 8N1），把
字节流交给与传输无关的 `CustomControllerLinkPolicy` 组帧、校验和解析，再按配置经
MQTT `CustomControl` 上行转发原始 30 字节控制段。

同时保留 **UDP 兼容路径**：当 `controller.serial=false`，或串口打开失败时，回落到
`controller.listen_port`（默认 3340）的 UDP 监听，用于旧 RJ45 链路和无硬件联调。

## 结果

正面影响：

- 现场链路与控制器实际物理接口（RS232）一致，不需要额外的网络设备。
- 转换器在主机侧表现为普通串口，Qt `QSerialPort` 直接可用，不依赖厂商 SDK。
- 解析层与传输层解耦：串口、虚拟串口、UDP 和测试注入共用同一个 `feed()` 入口。
- 保留 UDP 路径后，没有转换器也能用 `tools/controller_link_emulator.py` 验证解析。

代价与约束：

- RS232-USB 转换器的芯片、驱动和供电质量会影响链路稳定性，需要选用成熟型号。
- 设备名随主机和端口变化（`/dev/ttyUSB0` / `COM5` / `/dev/ttyACM0`），必须通过
  `controller.serial_port` 或 `RM_CONTROLLER_SERIAL` 指定，不能写死在代码里。
- 串口一旦配置错误或转换器被拔出，需要明确的错误上报和回落逻辑，不能静默失败。

## 备选方案

| 方案 | 评估 |
| --- | --- |
| RS232 转以太网（串口服务器） | 需要额外设备与网络配置，延迟和故障点更多；仅在需要远距离或隔离部署时更优 |
| RS232 转 Wi‑Fi | 时延抖动和丢包不可控，不满足 30 Hz 稳定输入 |
| 控制器改用原生 USB CDC | 需要改控制器固件与 PCB；原生 USB 全速 1 ms 轮询在高频下抖动更明显，且控制器已用 USB 做电机状态调试，链路会更复杂 |
| RS485 + USB 转换器 | 适合多点总线；本场景是点对点，RS232 已足够 |
| 纯 UDP（原 RJ45 方案） | 依赖控制器侧有网络接口；控制器只有 RS232，需要额外转换设备，反而更绕 |

## 重新评估条件

出现以下情况时重新评估本决策：

- 控制器硬件改为带以太网或原生 USB 的主控，且能直接提供稳定链路。
- 现场转换器在长时运行中出现明显丢帧、掉线或驱动冲突，且无法通过型号更换解决。
- 规则进一步要求控制器与客户端使用同一条已定义的官方链路，而不再是 RS232。
